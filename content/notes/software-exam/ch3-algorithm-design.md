# 第三章：算法设计与分析

## 分治法

对于一个规模为n的问题，若该问题可以容易地解决（比如说规模n较小）则直接解决，否则将其分解为k个规模较小的子问题，这些子问题**互相独立且与原问题形式相同**，**递归**地解这些子问题，然后将各子问题的解合并得到原问题的解。

要求：

- 该问题的规模缩小到一定的程度就可以容易地解决
- 该问题可以分解为若干个规模较小的相同问题
- 利用该问题分解出的子问题的解可以合并为该问题的解
- 该问题所分解出的各个子问题是相互独立的。

一般来说，分治算法在每一层递归上都有3个步骤。

1. **分解**：将原问题分解成一系列子问题。

2. **求解**：递归地求解各子问题。若子问题足够小，则直接求解。

3. **合并**：将子问题的解合并成原问题的解。



### 递归

在运行的过程中自己调用自己

下面为求整数的阶层

```java
public static void main(String[] args) {
    Scanner sc = new Scanner(System.in);   // 键盘录入
    System.out.println("请输入一个整数");
    int num = sc.nextInt();                // 获取用户输入的整数
    int ans = factorial(num);              // 调用方法
    System.out.println("阶层为" + ans);
}

private static int factorial(int num){
    // 如果 num 比 1 大，则num - 1后继续调用自身，并将值全部相乘
    if(num > 1){ 
        return num * factorial(num - 1);   // 递归调用
    }else{
        return 1;
    }
}
```

函数递归调用带来的内存开销：S(n) = O(n)

**空间复杂度=递归调用的深度**



## 动态规划法

**特征：子问题不独立**（与分治法的区别）

基本思想是将待求解问题分解成若干个子问题，先求解子问题，然后从这些子问题的解得到原问题的解。

与**分治法**不同的是，适合于用动态规划法求解的问题，经分解得到的子问题往往**不是独立的**。

动态规划算法通常用于求解具有**某种最优性质的问题**。

在这类问题中，可能会有许多可行解，每个解都对应于一个值，我们希望找到具有
最优值的那个解。当然，最优解可能会有多个，动态规划算法能找出其中的一个最优解。

**特征：寻找<u>整体</u>最优解**（与贪心法的区别）

对一个给定的问题，若其具有以下两个性质，则可以考虑用动态规划法来求解。

1. **最优子结构**：如果一个问题的最优解中包含了其子问题的最优解，就说该问题具有最优子结构。当一个问题具有最优子结构时，提示我们动态规划法可能会适用，<u>但是此时贪心策略可能也是适用的</u>。
2. **重叠子问题**：指用来解原问题的递归算法可反复地解同样的子问题，而不是总在产生新的子问题。即当一个递归算法不断地调用同一个问题时，就说该问题包含重叠子问题。此时若用分治法递归求解，则每次遇到子问题都会视为新问题，会极大地降低算法的效率，而动态规划法总是充分利用重叠子问题，对每个子问题仅计算一次，把解保存在一个在需要时就可以查看的表中，而每次**查表的时间为常数**。



## 贪心法

**特征：寻找<u>局部</u>最优解**

总是做出在当前来说是最好的选择，而**并不从整体上加以考虑**，它所做的每步选择只是当前步骤的**局部最优选择**，但从整体来说不一定是最优的选择。由于它不必为了寻找最优解而穷尽所有可能解，因此其耗费时间少，一般可以快速得到满意的解，但得不到最优解。也常用于**解决最优化的问题**。

用贪心法求解的问题一般具有两个重要的性质。

1. **最优子结构**：当一个问题的最优解包含其子问题的最优解时，称此问题具有最优子结构。问题的最优子结构是该问题可以采用动态规划法或者贪心法求解的关键性质。
2. **贪心选择性质**：指问题的整体最优解可以通过一系列**局部最优**的选择，即贪心选择来得到。这是贪心法和动态规划法的主要区别。



## 回溯法（深度优先搜索法）

回溯法是种选优搜索法，按选优条件向前搜索，以达到目标。但当搜索到某一步时，发现原先选择并不优或达不到目标，就退回一步重新选择。

这种走不通就退回再走的技术就是回溯法。

比如走迷宫，如果走不通就返回到上一个岔路口走另一条路



快速排序算法在排序过程中，在待排序数组中确定一个元素为基准元素，根据基准元素把待排序数组划分成两个部分，前面一部分元素值小于基准元素，而后面一部分元素值大于基准元素。然后再分别对前后两个部分进一步进行划分。根据上述描述，快速排序算法采用了\_\_\_\_算法设计策略。
已知确定着基准元素操作的时间复杂度为O(n)，则快速排序算法的最好和最坏情况下的时间复杂度为\_\_\_\_

A.分治		B.动态规划		C.贪心		D.回溯

A. O(n) 和 O(n log n)			  B. O(n) 和 O(n^2^)
C. O(n log n) 和 O(n log n)		D. O(n log n) 和 O(n²)



解析：将数组划分为多个小部分，可能是分治法或是动态规划法。不断划分，得到的子部分和原部分相似但又互相独立，选A。

最好的情况下是一半在基准元素的左边，一半在右边，每次划分都是左右均匀对称，递归的深度为log n ，每层遍历 n 个元素 ，这种时间复杂度为O(n log n)
最坏的情况是一边几乎没有，全在另外一边，需要划分 n 层，时间复杂度为O(n^2^)

### 0-1背包

**特点：基于动态规划法**

有 `n` 个物品，每个物品具备 **重量 `w[i]`** 和 **价值 `v[i]`** 两个属性，背包有固定容量 `capacity` 。由于每个物品只有选（1）或者不选（0）两种状态，在此条件下，要找出能使背包所装物品价值最大的选择方案

![image-20250623151047144](C:\Users\19354\AppData\Roaming\Typora\typora-user-images\image-20250623151047144.png)



**初始条件**

- 当背包容量 `c = 0` 时，没有空间装任何物品，所以最大价值 `dp[0] = 0` 
- 当没有物品可选（也就是 `i = 0` ，还未开始处理物品时 ），不管背包容量多大，最大价值都是 `0` ，即 `dp[0][c] = 0`（二维数组场景 ）



**一维数组代码实现**

```java
public static int zeroOneKnapsackDPCompressed(int capacity, List<Integer> w, List<Integer> v) {
   // 初始化一维 dp 数组，dp[c] 表示容量为 c 时的最大价值
   int[] dp = new int[capacity + 1]; 
        
    for (int i = 0; i < w.size(); i++) { 
       // 逆序遍历容量，保证每个物品只选一次，体现 0-1 背包特性
       for (int c = capacity; c >= w.get(i); c--) {                 // 状态转移：选当前物品与不选当前物品的情况取最大值
        dp[c] = Math.max(dp[c], dp[c - w.get(i)]+ v.get(i)); 
        }
      }
     return dp[capacity]; 
    }
```

时间复杂度 O(n*capacity)

空间复杂度 O(capacity)

详解：以背包的容量为初始值，倒序遍历，初始化时`capacity + 1`是因为数组索引从0开始，要 `+ 1` 才能与背包的容量对应。该数组代表从`0` 到 `capacity` 的最大价值。然后依次对每一件物品进行比较，比较装这件物品和不装这件物品哪个更好，并覆盖在数组对应的位置上。全部比较完后数组最后的值就是最终答案。倒序遍历是为了防止干扰，因为正序的话可能会装入两个相同的物品。

下面示例中容量0\~5就是数组索引0~5的值

**示例  （物品 `w = [2,3,4,3]`、`v = [3,4,5,5]`、容量 `capacity = 5` ）**

| ----------------- | -------- | ---- | ---- | ---- | ---- | ---- | ----------------------------------------- |
| 初始              | 0        | 0    | 0    | 0    | 0    | 0    | 初始化                                    |
| 处理物品 1（2,3） | 0        | 0    | 3    | 3    | 3    | 3    | c≥2 时，dp [c] = dp [c-2]+3               |

**代码实现**

```java
 public static int completeKnapsack(int capacity, int[] w, int[] v) {
        int[] dp = new int[capacity + 1]; // dp[c] 表示容量 c 的最大价值
        
        for (int i = 0; i < w.length; i++) { // 遍历每种物品
            for (int c = w[i]; c <= capacity; c++) { // 正序遍历容量（从 w[i] 开始）
               dp[c] = Math.max(dp[c], dp[c - w[i]] + v[i]);
            }
        }
        
        return dp[capacity];
    }
```

**示例 （物品 `w = [2,3]`、`v = [3,4]`、容量 `capacity = 5` ）**

| 步骤             | `dp[0]` | `dp[1]` | `dp[2]` | `dp[3]` | `dp[4]` | `dp[5]` |
| ---------------- | ------- | ------- | ------- | ------- | ------- | ------- |
| 初始             | 0       | 0       | 0       | 0       | 0       | 0       |
| 处理物品 1 (2,3) | 0       | 0       | 3       | 3       | 6       | 6       |
| 处理物品 2 (3,4) | 0       | 0       | 3       | 4       | 6       | 7       |



**核心逻辑对比（0-1 背包 vs 完全背包）**

| 对比项         | 0-1 背包（逆序遍历）              | 完全背包（正序遍历）              |
| -------------- | --------------------------------- | --------------------------------- |
| **遍历顺序**   | `j` 从 `capacity` 到 `w[i]`       | `j` 从 `w[i]` 到 `capacity`       |
| **状态转移**   | `dp[j]` 依赖上一轮的 `dp[j-w[i]]` | `dp[j]` 依赖当前轮的 `dp[j-w[i]]` |
| **允许重复选** | 不允许（每个物品最多选 1 次）     | 允许（同一物品可重复选）          |
| **示例结果**   | 最大价值为 6（选两次 `2`）        | 最大价值为 7（选 `2+3`）          |



### 部分背包（分数背包）

**特点：基于贪心法**

物品：可以分割，能取1/2、1/3、任意比例

目标：在背包容量内总价值最大

思路：

1. 先计算每个物品的单位重量价值：价值 / 重量
2. 按单位重量价值从高到低排序并放入背包

时间复杂度：**O(n log n)**（排序开销）



### 背包问题总结

0-1 背包：

1. 只能拿完整的一个 → 动态规划法
2. 不能用贪心法，结果会出错
3. 时间复杂度 O(n*capacity)

完全背包：

1. 可重复拿 → 动态规划法
2. 不能用贪心法，结果会出错
3. 时间复杂度 O(n*capacity)

部分背包：

1. 可分割 → 贪心法
2. 时间复杂度 O(n log n)
